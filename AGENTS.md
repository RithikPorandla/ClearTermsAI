# AGENTS.md

## Cursor Cloud specific instructions

### Project overview

ClearTerms AI is a multi-project repo (not a monorepo with workspaces) with three independent components:

| Component | Path | Port | Run command |
|-----------|------|------|-------------|
| Express API server | `server/` | 8787 | `node src/index.js` |
| Next.js web dashboard | `web/` | 3000 | `npx next dev` |
| Chrome Extension | `extension/` | N/A | Load unpacked in Chrome |

Each of `web/` and `server/` has its own `package.json` and must have `npm install` run independently. There is no top-level `package.json`.

### Running services

- **Server**: `cd server && node src/index.js`. Requires a `.env` file (uses `dotenv`). Without `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`, the `/analyze-policy` and `/reports` endpoints return 500; `/health` always works. Without `AUTH0_DOMAIN`/`AUTH0_AUDIENCE`, auth falls back to `user = "anon"`.
- **Web**: `cd web && npx next dev`. Requires `.env.local` (see `web/.env.example`). Auth0 env vars must be present or the Auth0 SDK will throw on import; use placeholder values for local dev if Auth0 is not configured.

### Lint and type checking

- No ESLint is configured in the repo (`next lint` prompts for interactive setup).
- TypeScript type-check for web: `cd web && npx tsc --noEmit`
- Build check for web: `cd web && npx next build`
- Server is plain JS (ES Modules), no type-check or lint configured.

### Environment variables

Server (`server/.env`):
- `PORT` (default 8787), `CORS_ORIGINS`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, `AUTH0_DOMAIN`, `AUTH0_AUDIENCE`, `INTERNAL_API_KEY`

Web (`web/.env.local`):
- `NEXT_PUBLIC_API_BASE_URL`, `AUTH0_SECRET`, `AUTH0_BASE_URL`, `AUTH0_ISSUER_BASE_URL`, `AUTH0_CLIENT_ID`, `AUTH0_CLIENT_SECRET`, `AUTH0_AUDIENCE`

### Gotchas

- The `web/` app uses both Next.js App Router (`app/`) and Pages Router (`pages/`). The landing page is in `app/page.tsx`; API routes and the reports page are in `pages/`.
- `web/.env.local` Auth0 variables must be set (even to placeholder values) or the `@auth0/nextjs-auth0` SDK will error during import on the API route pages.
- The `tsconfig.json` in `web/` is auto-generated by Next.js on first build/dev run; it is not checked into the repo.
- The extension has no build step; it is vanilla JS loaded directly into Chrome via "Load unpacked".
